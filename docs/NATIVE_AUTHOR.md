# Direct Codex backlog authorship

The owner requested direct JKSimmons writing across every category, with context, standards, durable batches and approved publication. The installed `ncce-backlog-writer` skill uses the dedicated `/api/native-author/` POST boundary, separately from review queue jobs and JuniorWriter provider calls. Existing private bridge credentials authenticate it; the server further restricts the declared thread to configured JKSimmons. No new secret, schema migration, scheduled model use or changes to Workshop guideline activation are introduced.

`src/native_author.py` uses the real sample/catalog, active shared/form instructions, current labelled RAG and reviewer standards. All 15 forms have category-specific skill references and dependency ordering. Missing virtual territory scenes use a read-only factual/place packet; only approved publication creates a fictional slot. A native author plan is the author’s work, not falsely labelled an exact historical API request.

Operations: catalog/context, start, prepare, save, status/batches, stop, publish. Batches store selected eligible target keys and explicit maximum 1–200 native draft reservations. Reserve before model work; reservations are idempotent by request key, capped at five per entry and blocked behind an unresolved reservation. Uncertain dispatch never silently renews allowance. Saved drafts/output/checks and frozen source preimages are immutable. Stop prevents new reservations but permits saving existing work. These helpers do not execute models or make an idle author continue.

Default batches are missing-only and draft-only. Explicit replacement mode permits generated existing records, never authored/canon/inactive sources. Publication needs the saved draft’s exact confirmation hash and owner approval through the invoking agent. The hash proves identity, not human consent: no claim of cryptographic owner attestation is made. Fresh source/context/guideline identity, actual target equality and writer-pipeline exclusion guard publication. The server validates prose formatting and known metadata leaks; source fidelity and literary quality remain author checks/human judgment, not an independent critic.

Publication reuses protected population write mechanics with a new default-off `allow_existing` option supplied only by explicitly selected native replacement batches. Artifact predecessors remain in the existing version store. Mutable event/memory/thought rows have full preimages and output in the immutable native draft audit. Scene creation uses generate=False and connective_fiction, never a mechanical event. Native provenance marks native-codex rather than the external provider model. Existing category population/listener controls, API budgets and guideline pointers are not changed.

Private configuration remains `C:/Codex/NCCE/.codex-review-bridge/config.json`. The standalone installed skill client restricts destinations to the existing HTTPS preview or loopback, refuses redirects, saves full responses privately and prints bounded manifests; hash-checked JSON pointer reads prevent console truncation. Durable local feedback/standard events remain separate from active app guidelines and are read by the skill at batch start and after corrections. The optional SQLite snapshot reader stays explicitly read-only and never pretends to be current hosted data.

Validation uses disposable synthetic campaigns, fake HTTP responses and forbidden provider calls. Tests cover all form discovery, actual context export, auth/thread scope, immutable/idempotent drafts, bounded reservations, generated replacements, stale guideline refusal, protected targets, scene lifecycle/no mechanics, no writer/reviewer jobs, client host/hash guards and existing population/production/Workshop regressions. Hosted rollout verification must use read-only catalog/context only; do not create live prose or reservations merely to test installation.
